CreatureGathererFX — Game Design Spec

Creature-collecting demake for the Arduboy FX (ATmega32u4), rendered in native 1bpp at 52 fps. A compact overworld where you gather lures, trigger wild creature duels, win or capture creatures, grow them by experience and evolution, and keep a 64-slot persistent collection on the cartridge.

1. Overview, pillars, non-goals

CreatureGathererFX is a Pokémon-style creature collecting demake compressed onto a 128×64 monochrome screen with roughly 23 KB of usable program flash. The design deliberately trades depth for readability: five creature types in a complete rock-paper-scissors web, one flat damage table, hidden simultaneous picks, and a single persistent save on the FX cartridge. Gathering is the second core verb: lure zones turn ordinary wild battles into capture (“gather”) encounters with a progress clock.

Design pillars

  • Legible at 128×64. Every battle decision must be explainable by the type chart and the pick row; no hidden damage formula, no PP ledgers, no stat-stage homework.
  • One flat table. Damage is 14 win / 4 chip / 6 trade, scaled only by type matchup (×1.5 / ×0.5).
  • Gather, don’t just fight. Lures create dedicated zones; gatherable wild battles bank progress toward capture instead of a knockout.
  • Persistent collection. 64 stable instance slots on cartridge flash, journaled and compacted against power loss, each instance carrying its own species, experience, HP and attack kit.
  • Authored data, validated in host tools. Content constraints (evolution edges, encounter tables, script profiles) fail generation or tests, not the device.

Engineering priorities

  • Correctness of requested outcomes and mechanics comes first; measured smallest firmware second.
  • Whole-image flash/RAM measurement decides; per-symbol sizes are only leads.
  • Metadata reads (FX/OLED share SPI) happen on transitions only.
  • Trust authored/internal invariants; no runtime defenses for impossible states.
  • Tests prove mechanics and hardware outcomes, live permanently beside the code.

Non-goals

  • No audio yet (feasibility epic 7v13 only).
  • No multiplayer/link features.
  • No stat spreads, statuses, PP, accuracy or turn order — removed with the duel RETIRED.
  • No animation framework; battles are staged single-frame updates with timed phases.

3. Core gameplay loop

 walk the area ──► face a deposit tile + A ──► deposit a lure
      │                                            │
      │ step onto an encounter tile (10% roll)     ▼
      ▼                                     active lure zone (rate 1/2/4)
 wild duel begins ◄──────────────┐              │
      │                          │              │
      ├─ WIN (ordinary wild) ─► exp to living party,  material drop
      ├─ WIN (gatherable) ────► GATHER progress banks toward capture
      │                          │
      │                          └─ progress reaches need ─► GATHERED: instance written to collection (64 slots)
      ├─ ESCAPE (wild only) ──► return to world on the same tile
      ├─ LOSE / DRAW ─────────► defeat recovery: party healed, returned to start
      └─ FLED (gather clock ran out) ─► battle ends, no capture

Growth runs on the same terminal edge as rewards: ordinary wild wins grant experience to every living party member, which can raise levels, grow max HP, and trigger authored evolution. The collection is the end game: gathered instances keep their species, level, attack kit and damaged HP state across resets.

The shipping profile is the compact warp VM: one forward pass over a 128-byte slot per chunk, big-endian operands, only If / TpIf / End. 5. Encounters

Wild battles trigger from world steps: after plants tick and lure decay, the step commit checks the destination tile. If the tile carries PROP_ENCOUNTER, a 10% roll starts an encounter. Selection is deterministic per zone:

  • Zone definitions are packed per chunk: base table, table count, a 4-way lure-type nibble map, and a signed level offset.
  • An active lure zone selects a table by its type nibble (types 0–3 exposed); inert zones use the base table.
  • A slot is rolled from 10 entries; the wild level is clamp(floor(party average level) + zone offset, table floor, table ceil).
  • The encounter catalog is 32 species in shipping (ids 0–31); ids 32–63 are the opt-in expansion roster used by test builds only.

First-beta tables CONTRACT

data/beta-area.toml pins exactly five 10-slot tables (base + spirit/water/wind/earth lure groups), levels 2–5, allowed species [0, 3, 6, 9, 10, 12, 13, 14]. Placeholder species (21/22) and expansion ids are excluded. These authored tables become packed encounter data when the map integration lands; the currently packed generic zone data uses the same two test chunks with level offset 0.

6. Lures, zones & gathering

Lure items

Lures are the primary resource. Item id = type × 3 + tier (8 authored types × 3 tiers = 24 ids). Tier sets the zone charge and the gather rate:

TierNameCharge (steps)Gather rate
0crude161 / round
1fine322 / round
2pure644 / round

Types: spirit, water, wind, earth, fire, lightning, plant, elder. Encounter tables distinguish only the four low groups (spirit / water / wind / earth); higher types are future area content.

Depositing and zone life

  • Face a deposit tile (PROP_SPARE), press A, pick a lure from the 5-row picker. One lure is consumed.
  • A zone belongs to the chunk where it was deposited, carries the lure’s type and tier, and burns 1 charge per committed world step.
  • Leaving to a chunk without an authored zone clears the lure; expiry clears it and shows the “Lure Gone” feedback.
  • While active, wild encounters on that chunk are gatherable and use the lure-type table.

Gathering in battle

  • Gatherable battles expose a GATHER action (wild only; trainer/boss battles refuse it).
  • Each gather round adds the tier rate (1/2/4) to progress; the need is clamp(8 + wildLevel / 2, 8, 24) → levels 2–5 give 9–10.
  • Fleeing is automatic at 6 gather rounds; a KO on either active pauses the countdown (progress is retained).
  • Reaching the need captures the foe at its current HP into the collection; a full 64-slot store refuses losslessly.
  • The renewable math (authoring contract): tier-1 = 2 progress × 6 rounds = 12 ≥ need 10, so a fresh player can capture without KO risk or first-battle luck.
The first-beta renewable loop is partially implemented: plant-claim tiles currently grant a lure directly, and the staged planting/harvest model is planned (jp8.11.5). See §12.

7. Battle: the five-type duel

The shipped battle is a hidden-simultaneous-pick duel over a five-type complete tournament. Both sides commit a hidden action; the round resolves atomically; the round feedback reveals both picks and the damage. No turn order, no PP, no accuracy, no statuses.

Type web

Round resolution

CaseResult
Attack vs attack, one beats the otherWinner deals 14, loser chips 4
Attack vs attack, mirror or neutralBoth deal 6 (trade)
Exactly one side switchesThe non-switching side lands a default win (14) against the incoming creature
Both switchNo damage
Exactly one side waitsThe other lands a default win (14)
Both wait / unusable kitNo damage

Every attack then multiplies its base by its own matchup against the defender: ×1.5 if the move type beats any of the defender’s types, ×0.5 if it loses to any, otherwise ×1 (advantage checked first; no stacking of dual weaknesses). Fixed-point tenths, rounded up, minimum 1. Both damages are computed against the same pre-hit state and applied together, so simultaneous KOs are exact; if both sides are wiped the duel is a DRAW. A KO on a member that was swapped in reverts to the (living) outgoing member; otherwise the first living member promotes.

Attack kits

A creature’s moveset is a 5-bit attack mask: one bit per duel type. The pick row shows one option per set bit, in ascending type order. Mask 0 means no usable attack (the pick row degenerates to WAIT). Each instance carries its own mask in the save record; species data carries the default kit. Trainer presets author masks per member.

Opponent AI (personas)

PersonaModelDefault read rate
randomNever reads; still prefers its best creature-matchup tier0%
readerCounters your last revealed type25%
frequencyCounters your most-used revealed type50%
anti-repeatModal type with the newest pick discounted50%

On a reading turn: pick a countering attack if the active kit has one; otherwise switch to a living bench member that counters; otherwise attack uniformly. On a non-reading turn: prefer the best creature-matchup tier, then uniform. Read rates are capped below 75% because a fully reading opponent is exploitable by predictable rotation. The AI reads only revealed history and public state — never the hidden pick. Wild battles use random/0; trainer personas in the current build are a temporary trainerId % 3 fixture (reader 25 / frequency 50 / anti-repeat 50) — the authored data/duel.toml persona table is generated but not yet consumed by firmware.

Session flow & timing LIVE

  • Choice: the pick row (attack cells, SWAP, WAIT) plus an action page (GATHER / ESCAPE) when legal. The opponent’s hidden pick is committed on Choice entry from the shared RNG.
  • Conceal phase: 29 frames (~558 ms at 52 fps) between commitment and reveal.
  • Reveal + resolution: one atomic round; result dwell runs 68 frames (~1308 ms); A accelerates feedback.
  • HP ownership: the session writes damage back to player.creatureHPs by original party slot at the terminal edge; the world battle syncs HP both ways.
  • Terminals: WIN / LOSE / DRAW / GATHERED / ESCAPED / FLED. LOSE and DRAW run defeat recovery (party healed, player returned to the authored start). ESCAPE is immediate on selection for wild battles.

Rewards on the terminal edge

  • Ordinary wild win: every living occupied party member gains 8 × foe level exp; the foe species’ authored material drops once (saturating bag).
  • Gatherable win (captured): the foe instance is written to the 64-slot collection with species, current exp, attack mask and HP-encoded state; no exp and no material.
  • Trainer/boss win (planned for beta): authored victory flag gates the ending; no repeated reward.
  • Gathered/Fled/Escaped/Lose/Draw award nothing.

9. Progression: levels, evolution, stats

Experience & levels

  • Curve: cumulative exp for level L is L³ (level 1 = 1 exp), stored as a 32-entry u16 table; cap 29,791 at level 31. Level is derived from exp — it is never stored.
  • Gain: 8 × foe level per ordinary wild win, to every living occupied party member, saturating at the level-31 threshold.
  • Level-up effect: max HP is recomputed from species seed and level; a living member keeps its missing HP (HP grows by the max-HP delta, capped at the new maximum).

Stats model PLANNED

Authoring currently carries six stat seeds per species (atk, def, spcAtk, spcDef, hp, speed), but the duel reads only hp: max HP = 2×level + hpSeed×(level/3) + 30. The five other seeds are unread in shipping and their trials were measured inert (e.g., a special-defense seed change moved 0/25 matchup pairs). Owner decision (2026-10-17): retire the five dead seeds, keep HP as the only stat, and make the attack mask the progression/customization axis — evolution unlocks types now, item-driven custom kits later. One attack-scaling seed and a per-level learnset table remain parked options (see §20).

Evolution

  • Edges are explicit authored from → to @ level mappings; id adjacency is never inferred. The generator validates duplicates, self/missing targets, thresholds, kit presence and cycles before packing.
  • Live beta edges: 0→1, 3→4, 6→7, each at level 8 (the starter trio).
  • On the same wild-win terminal edge as exp: an instance at or over its edge threshold replaces its species in place, preserving exp, stable slot and current mask, and recomputing types/HP at the unchanged derived level; a living member keeps its missing HP.
  • A refused save write leaves the old species in place — the evolution stays derivable from exp and retries on the next eligible transition. The collection path can evolve boxed instances the same way.
  • PLANNED Growth rearch (rhs7): author the full starter chains (1→2, 4→5, 7→8 at level 16) and adopt the target species’ kit on evolution, which restores the “instance kit == species kit” invariant and turns stage transitions into type unlocks (crab gains fire at 8; snail gains plant and squid gains fire at 16).

12. Plants

  • Model: 32 plant indices, each with a 2-bit stage (0–3) packed into 8 bytes; two plant pairs of (3-bit type + active flag) per byte.
  • Growth: a 128-step world ticker increments every stage (mod 4) for each committed step; the ticker and stage bytes persist in the save snapshot.
  • Planned staged loop (jp8.11.5): face a plantable tile, A plants free (stage 1); stage 3 (mature) + A grants one tier-1 lure and resets to stage 1; maturity is held rather than overflowing a full bag.
  • Today the plant-claim tile grants one lure directly as a placeholder, and the authored plant source (type 0 / tier 1) is generated but not yet read by firmware.

13. Party, collection & save system

Player & party

  • Active party: 3 creature slots (Player.party[3]) plus live HP per slot (creatureHPs[3]); the same HP array is the battle contract.
  • Heal party restores occupied slots to derived max and clears transient status; empty slots are skipped.
  • Fresh games start from the authored beta preset (species 0/3/6 at level 3, kits water/earth/water), seed three stable store instances, and start at the authored tile (11, 5).

Collection & instance records

The collection is 64 eight-byte stable records (StoreRecord): species id, cumulative exp (u16), folded attack mask, 3 reserved bytes (zero), and an HP byte. HP encoding: 0 means full/derived max, otherwise HP − 1 — this keeps the legacy “full” case free and encodes damaged instances exactly. Instances are the growth authority: level, max HP, evolution and (planned) kit all derive from the record.

Persistence architecture

LayerDesign
SnapshotSaveFile v3, 96 bytes: location, 8 flag bytes, party slots + HP, plant stages/pairs/ticker, 24 lure counts, 8 consumable counts, 4 key-item bytes
Journal16-byte append records (StoreAdd / StoreRemove / PartyAssign); 256 records per sector; torn-tail detection via a final marker byte written last, so an interrupted append is un-overwritable and treated as end-of-log
CompactionAlternating A/B checkpoints with header magic, generation counter, dual checksums and commit bytes; validate, erase the journal, verify blank
Sectors8 sectors × 4,096 B: main snapshot 0, journal 4096, store A 8192, store B 12288, four reserved sectors
CadenceExplicit checkpoints (no autosave yet). Collection writes journal immediately; an explicit SAVE from the world menu is planned (jp8.11.23)

15. Content pipeline & tooling

All content flows through one native generator (cgfx-tools, Rust) driven by make gen:

data/json/creatures.json ─┐
maps/world_map.json ──────┤
data/*.toml contracts ────┤   cgfx-tools --project cgfx-project.json
data/*.csv tables ────────┼─► fxdata/generated/*  (headers, tables, fixtures)
images/*.png, text ───────┘        │
                                   ├─ copies: opcodes.hpp → src/vm, flags/* → src/flags
                                   ├─ fixtures → tst/fxdatatest/generated
                                   └─ pack (fxlayout.toml) → src/fxdata.h + dist/fxdata*.bin
  • fxlayout.toml is an ordered flash layout (30 packed entries + 8 save sectors); declaration order is permanent ABI. Save offsets are sector-aligned and stable.
  • Sprites/fonts regenerate natively from fxsprites.toml; the string table renders into a packed glyph sheet.
  • make verify-generated checks the manifest (inputs, outputs, hashes) without mutating; test-pack-parity pins the packed image SHA-256; test-manifest / test-generated-libs prove the packed bytes match the published header.
  • Generated files are never hand-edited; change the JSON/CSV/TOML/PNG source and regenerate, staging the generated set as one commit.

17. Testing & evidence rules

  • Host: C++ suites exercise kernel rules, session/flow wiring, save/journal/compaction, world stepping, encounters, menu navigation, arena lifecycle. Latest counts: ~240.5k passed / 0 failed, world suite 258 / 0, VM 286 / 0.
  • Device: 34 headless Ardens suites run the real firmware paths through serial, accepting only an exact P/F marker. Highlights: duel kernel relations and damage, real-session timing (29/68 frames), UI geometry/captions, painted stack headroom, save cuts/journal/flag extents, table read paths, script VM, FX read counter.
  • FX read rule: program-data reads occur on transitions only. The counter resets per frame; steady-state update must add zero reads, render is checked exactly, and transition owners declare their exact reads.
  • Determinism: RNG is seeded from hardware entropy on boot and injectable in tests; the duel kernel has a C++/JS parity check (make sim-test) against the canonical mock.
  • Evidence: every resource-changing item keeps a same-source control A/B, the touched device suites, and a compact report (commands, numbers, wall time, storage).
